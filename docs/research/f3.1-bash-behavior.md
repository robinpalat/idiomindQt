## 1. On-disk formats (empirical, real data)

### 1a. data line — WRITER format (14 fields)
Created by `ifs/mods/add/add.sh:55 index()` via `eval newline="$(sed -n 2p $DS/default/vars)"` + `echo "${newline}" >> data`.
Field order exactly:
```
trgt{...}srce{...}exmp{...}defn{...}note{...}wrds{...}grmr{...}tags{...}mark{...}refr{...}imag{...}link{...}cdid{...}type{1|2}
```
- type 1 = word => writer `unset wrds grmr link defn` beforehand (empty segments).
- type 2 = sentence => `unset defn`.
- Every append ends with newline (`echo`). No blank line between items; check_index later removes blanks.
- Duplicate guard on append: `grep -Fo "trgt{${trgt}}" data` must NOT match, else item silently skipped.
- `}` inside any value is not representable (all parsers split on `}`).
- Leading/trailing whitespace of a line is STRIPPED by the repair paths (`line.strip()`).

### 1b. data line — WEBSITE/import format (25 fields)
Produced at import `main.sh:326-329`: takes the `.idmnd` JSON line (`vars` line 1), `tr -d '\\'`,
then `sed 's/},/}\n/g;s|","|}|g;s|":"|{|g;s|":{"|}|g;s/"}/}/g'`, `s/^\s*./trgt{/g`, `/^$/d`.
Field order:
```
trgt{...}srce{...}slch{}slde{}slen{}sles{}slfr{}slit{}slja{}slpt{}slru{}slvi{}exmp{...}defn{...}note{...}wrds{...}grmr{...}tags{...}mark{...}refr{...}imag{...}imgr{...}link{...}cdid{...}type{1|2}
```
Verified in real topics: "Testiando"=14, "Mi colección de November"=14, "Beach"=14,
"August 2013"=25, "Eating and drinking"=25, "April collet 2"=25 (first line), and
**"VSFS Interview 2014 London" is MIXED (10 items x14 fields + 22 items x25 fields)**
=> any parser/writer MUST handle both per line. Real files have a trailing newline after last line.

### 1c. .conf/index format
3 lines per item, only for items present in the `learning` table:
```
<text-of-item>\n
TRUE|FALSE\n
srce\n
```
- text is `<b><big>X</big></b>` when X ∈ marks table, `<span color='#AE3259'>X</span>` when ∈ log3,
  `<span color='#C15F27'>X</span>` when ∈ log2, else plain.
- chk line: TRUE only when (log1 && acheck==TRUE && flag arg==1), else FALSE; non-log1 items get FALSE.
- srce = field index 1 in BOTH formats.
- Written by `ifs/tls.sh:1005 colorize` (python loop over data lines, `item in learning`). Items not in
  learning are OMITTED. No blank separators. Count invariant: (non-empty index lines)/3 == learning count.
- `index` is regenerated, never directly edited, on every add/edit/delete (colorize), EXCEPT the
  initial append which writes `echo -e "${trgt}\nFALSE\n${srce}" >> index`.

## 2. check_index — full verbatim behavior (`ifs/tls.sh:73-294`)
Called as `tls.sh check_index <topic> [r=1]`. r=1 = quiet repair (no notify).

_check() (87-172) diagnostics:

- remove zero-size topic-level `*.mp3`.

- stts==13 => if stts.bk exists: stts = WHOLE FILE content; then `cleanups stts.bk` (remove), else stts=1;
  non-numeric => 1; `echo ${stts} > stts`; mkmn=1, fix=1.
- DB check: `file "$tpcdb"` must match 'SQLite' else `mkdb.sh tpc <topic>` + fix=1.
  Else: `select Count(*)` from reviews / id / config must each be 1 => else set db_reviews/db_id/db_config flags.
- stts > 1 and `date1` empty => `update reviews set date1='%m/%d/%Y'` (tpc_db 9).
- 0.cfg / id.cfg present => newform=1 (flag only, no action).
- `grep -o 'trgt{}srce{}' data` => fix=1 (marker of broken empty-template lines).
- read learning/learnt/words/sentences (tpc_db 5). Counts:
  - cnt0 = non-empty lines in data
  - index0 = non-empty lines in index / 3 (missing index => 0)
  - cnt1..4 = learning, learnt, words, sentences (non-empty)
  - `cnt3+cnt4 != cnt0` => fix=1 (words+sentences must equal data lines)
  - `cnt1+cnt2 != cnt0` => fix=1 (learning+learnt must equal data lines)
  - `if [ $? != 0 ]; then export fix=1; fi` — **DEAD CODE (no-op)** (verified: `$?` is the just-finished
    `if` exit status, always 0 in the branchless/export cases). Preserve as harmless, do NOT reproduce as "always fix".
  - `index0 != cnt1` => fix=1 (index must match learning count)
  - stts in {3,4,7,8,9,10} and cnt0==0 => `echo 1 > stts`; mkmn=1.

_restore() (174-242) — the fix:

## 3. Item lifecycle
### Add (append) — `ifs/mods/add/add.sh:55 index()`
- flock `$DT/i_lk`. If arg==edit: renames in DB (`tpc_db 7 <ta> <new> <old>` for learning learnt words
  sentences marks = `update ta set list='new' where list='old'`) + practice files (`sed -i "s|^old$|new|"`).
- else append: type param 1|2; guards trgt non-empty + .conf exists + `grep -Fo "trgt{${trgt}}"` absent.
  type1: words table + learning table; type2: sentences + learning. index `>>` 3-line group. data `>>` template line.
  (Data table insert is COMMENTED OUT in Bash => Data is populated ONLY at import; keep unchanged.)

### Update — `mngr.sh:113 edit_item` (and `index edit`)
- Item located by trgt (learning or learnt list, position). `edit_pos` = line number of `trgt{...}` in data.
- data line edited IN-PLACE with `sed -i "<line>s|field{old}|field{new}|..."` for
  type srce exmp defn note wrds grmr mark cdid (and trgt/grmr via an earlier global sed when renamed).
  => ONLY the changed field segments are replaced; all other segments (incl. any slXX/imgr) are preserved byte-for-byte.
- trgt rename => `index edit` renames it in tables + practice logs.
- type changed => move between words/sentences tables.
- .jpg renamed trgt->trgt_mod, audio file renamed when cdid changes.
- ends with (background) `colorize 1` => index regenerated.

### Delete — `mngr.sh:35 delete_item_ok` / `mngr.sh:70 delete_item`
- trgt; cdid = `grep -oP '(?<=cdid{).*(?=})'` of the item line.
- delete files `${DM_tlt}/<cdid>.mp3` and `${DM_tlt}/images/<trgt-lower>.jpg`.
- `sed -i "/trgt{${trgt}}/d" data` (exact-trgt line removal).
- practice logs: remove whole-line-exact matches, then `/^$/d`, rewrite in place.
- `tpc_db 4 <ta> list <trgt>` for learning learnt words sentences marks (delete where list=trgt).
- data lines <200 && `lk` present => remove `lk`. feeds topic => trgt appended to `exclude`.
- `colorize 1` (background). Reviews NOT touched, id counts (nwrd/nsnt) NOT adjusted (known quirk, document).

## 4. stts / stts.bk / note / tpc
- stts: single-line integer in `.conf/stts`. Read via `sed -n 1p`. Written whole-file. Valid {0..10}, 13.
  Non-numeric read => treated as 13 by check_index/tpc.sh.
- stts.bk: written by `ifs/mods/start/update_lists.sh:12`: topics with mtime >80 days: `mv stts stts.bk; echo 0 > stts`.
  Consumed by check_index (stts==13 => whole-file restore, then remove bk) and `tpc.sh:70-77`
  (re-enabling inactive topic: stts.bk => restore; if none => 13; then 13/0 => 1). Whole file content is used.
- note: created empty by check_file; `tpc.sh:19` creates with `echo " " > note` (single space). Whole-file read.
  Written on export (`upld.sh:38-41`): non-empty => `echo -e "\n${note_mod}" > note`, else plain.
  `mark_as_learned` does a content-preserving mtime bump (`cp note note.bk; sleep 1; mv note.bk note`).
- .conf/tpc is the per-topic SQLITE DB file. `$DC_s/tpc` (1-line topic name) is the active-topic marker.

## 5. tpc_db / cdb (cmns.sh) — exact SQL per mode (baby escapes: `'` -> `''`)
- 1 read `select <co> from '<ta>';` | 2 insert `insert into <ta> (<co>) values ('<va>')` (timeout 500)
- 3 mod `update <ta> set <co>='<va>'` (timeout 300) | 4 delete-specific `delete from <ta> where <co>='<va>'` (500)
- 5 select all `select * from '<ta>'` + `tr -s '|' '\n'` | 6 delete all (2000) | 7 mod-specific `update <ta> set list='<co>' where list='<va>'` (500)
- 8 insert-fast | 9 mod-fast `update <ta> set <co>='<va>'` | 10 select <co> limit 1
- 21/22 = BUGGY inserts (documented; do NOT reproduce for Data col mod/delete).
- `cdb` = same-ish for global config DB (`~/.config/idiomind/config`), adds `-cmd ".timeout 2000"`.
- NOTE: mode 5 with `tr -s '|' '\n'` collapses empty separators, so reviews count via
  `grep -c '[^[:space:]]'` = number of NON-EMPTY date fields regardless of column.

## 8. Design implications (Qt)
- FlatItemCodec must parse BOTH field orders and preserve unknown/extra segments (slXX, imgr) plus their exact
  bytes on write; appended NEW items use the 14-field template.
- writeItems = writer semantics: template render for new lines, in-place field-value replacement for edits,
  exact-line removal for deletes; preserve trailing newline; never write-on-read in loadItems.
- Index: only learning members; 3-line groups; regenerable via colorize-equivalent; (non-empty/3)==learning count.
- Reviews: single-row; load/store full date vector; repair preserves back to date8; date1 backfill rule.
- SqliteDatabase must expose raw "update tablename set col=val", "delete from ta where list=...",
  "select * -> rows-> cells" semantics to mirror tpc_db modes 1-9.
- TopicRepairService: _check diagnostics + _restore + db_config/db_reviews/db_id fixes + trigger index rebuild.
- mkmn/.share/index and Data-table writes and id-count maintenance: OUT of scope (document decisions, don't "fix").
- Tombstones: none (deletion is physical line removal; no soft-delete concept).
