# 03 - Internal data model (topic storage)

## Item file `$DC_tlt/data`
- One item per line (hard cap 200 lines).
- Each line is a **flat field sequence** (templated in `default/vars` line 2):

```
trgt{...}srce{...}exmp{...}defn{...}note{...}wrds{...}grmr{...}tags{...}mark{...}refr{...}imag{...}link{...}cdid{...}type{...}
```

- Read side (`get_item`): line is split by `}` + newline, each field parsed
  with `grep -oP '(?<=trgt{).*(?=})'`.
- NOTE: the **writer** preserves every field, and some older files carry extra
  fields (e.g. fields[24] `type` when parse index 13 fails — see
  `tls.sh check_index _restore` python, which tries index 13 then 24).
- `get_item` in `mods/cmns.sh` splits line and sources a `vars`-like set of
  `$trgt $srce $exmp $defn $note $wrds $grmr $tags $mark $refr $imag $link $cdid $type`.

Field meaning:
- `trgt`: target-language text of the item (word or sentence)
- `srce`: native-language translation
- `exmp`: example sentence (only for word items)
- `defn`: dictionary definition
- `note`: user notes
- `wrds`: word list / extracted words (`word_translation` pairs, `t_r` joined)
- `grmr`: part-of-speech tags from grammar colorizer
- `tags`: user tags
- `mark`: `TRUE` → marked (starred) in lists
- `refr`: reference / source URL
- `imag`: image reference name
- `link`: link/referee
- `cdid`: creation date id / uuid
- `type`: `1` = word, other = sentence (used to fill `words` / `sentences`)

## Index file `$DC_tlt/index`
- Display artifact regenerated by `colorize` (python3) when the topic becomes
  active, or `stts 5/6` custom build in mngr.
- Format: 3 lines per learning item:
```
<span color='#AE3259'><b><big>WORD</big></b></span>   (log3 → red; log2 → orange)
TRUE|FALSE                                             (checkbox "auto-check" flag)
src                                                    
```
- Only items in `learning` table are listed; marked items get `<b><big>`.
- Colors: log3 = `#AE3259`, log2 = `#C15F27`, log1 = plain, marked = bold+big.
- The `TRUE/FALSE` is `$acheck` if the item appears in `log1` (index practice)
  or practice history.

## Translations
- `$DC_tlt/translations/$LANG.tra` — full copy of `data` translated to `$LANG`.
- `$DC_tlt/translations/active` — current native language of the topic.
- `$DC_tlt/translations/$LANg.bk` — backup made right before regenerating a
  translation.
- Batch editing produces full rewritten `data` file.

## Backup `.bk`
- `~/.idiomind/backup/<topic>.bk`
- Flat format with section markers:
```
----- newest <date>
<data lines>            (up to 200)
----- oldest <date>
<older data lines>
----- end
```
- Written only if the newest backup is older than 2 days and data non-empty.
- Restore picks the newest (`1`) or oldest (`2`) slice (head -n200).

## Metadata `$DC_tlt/.conf/note` and `$DC_tlt/.conf`
- `note` file = topic info/description (exported as `info` in .idmnd).
- `slng.inf` / `note.inf` — messages shown by `promp_topic_info`; e.g. when
  native language of topic != current `slng` (mismatch warning).

## Rendering the topic (notebook)
- Topic main window is `notebook_1` (info) + `notebook_2` (index/practice) +
  `notebook_3` (manage) in `mods/main/items_list.sh`.
- Attachments opened as HTML (`att.html`) via `idiomind-htmlview` or `yad --html`,
  produced by `attatchments` in `tls.sh`.

## Word list / learning sources
- `words` table = all items with `type == '1'`.
- `sentences` table = all other items.
- `learning` table = items currently being learned (subject of reviews/index).
- `learnt` table = mastered items.
- `marks` table = marked items.
